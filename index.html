배경과 문제

프로모션 페이지와 패밀리 사이트를 운영하면서 기존 레거시 UI 코드를 계속 수정해야 했습니다. 수정 범위를 파악하기 어려우면 작은 변경도 다른 화면에 영향을 줄 수 있어, 코드를 기능별로 나누고 구조화하는 작업이 필요했습니다.

제가 한 일

  • 기존 레거시 코드를 분석하고 기능별로 분리하여 수정과 유지보수가 쉬운 구조로 개선했습니다.
  • 사용자 편의성을 고려한 UI 개선과 운영 중 발생하는 UI 이슈 대응을 함께 담당했습니다.

구조 개선 방식 재구성 예시

아래는 실제 파일이 아니라, 기능 단위 분리 방식을 이해하기 쉽게 다시 그린 예시입니다.

Before 
css/
  style.css        /* 모든 페이지 스타일이 한 파일 */
js/
  common.js        /* 페이지별 동작이 뒤섞임 */
After 
scss/
  base/            /* reset, 변수 */
  components/      /* button, form, card ... */
  pages/           /* 페이지별 스타일 */
js/
  modules/         /* 기능별 모듈 (탭, 팝업 ...) */

배경과 문제

신규 사이트를 제작하면서 폼 그룹, 리스트, 카드, 댓글처럼 여러 화면에서 반복되는 UI를 화면마다 따로 만들면, 수정할 때 모든 곳을 찾아 고쳐야 합니다. 그래서 UI를 아토믹 디자인 방식으로 나누어 구성했습니다.

제가 한 일

  • 신규 사이트 제작에 아토믹 디자인 방식을 적용해 UI를 재사용 가능한 컴포넌트 구조로 구성했습니다.
  • 폼 그룹, 리스트, 카드, 댓글 등 반복 UI를 컴포넌트화하고 HTML·SCSS·JavaScript를 기능 단위로 모듈화했습니다.
  • Vite와 SCSS 기반 개발 환경에서 UI와 스타일 코드를 관리했습니다.

해당 사이트는 이후 디자인이 전면 개편되어 현재 공개된 화면에서는 당시 구조를 확인할 수 없습니다. 아래는 같은 방식을 새로 작성한 예제입니다.

배경과 문제

학습 서비스에서는 마우스를 쓰기 어려운 사용자도 같은 기능을 이용할 수 있어야 합니다. 화면이 보이는 대로 동작하는 것만으로는 부족해서, 키보드 접근과 대체 텍스트, 포커스 처리를 기준으로 UI 구조와 인터랙션을 점검했습니다.

제가 한 일

  • 웹접근성을 고려해 UI 구조와 인터랙션을 개선했습니다. (키보드 접근, 대체 텍스트, 포커스 처리)
  • Video.js를 서비스 특성에 맞게 커스터마이징하여 학습용 비디오 모듈 UI를 작업했습니다.

재현 예제 1: 키보드로 이용하는 팝업 직접 작성

팝업을 열면 포커스가 팝업 안으로 이동하고, Esc로 닫으면 팝업을 연 버튼으로 돌아옵니다.

수강 안내

Tab 키로 팝업 안의 버튼만 이동합니다. Esc 키 또는 닫기 버튼으로 닫을 수 있습니다.

 
opener.addEventListener('click', () => dialog.showModal());   // 포커스가 팝업 안으로 이동
dialog.addEventListener('close', () => opener.focus());       // 닫으면 열었던 버튼으로 복귀

재현 예제 2: 재생 컨트롤의 이름과 상태 직접 작성

아이콘만 있는 버튼도 스크린 리더가 읽을 수 있는 이름이 있어야 하고, 재생 상태는 aria-pressed로 전달합니다. 실제 영상 대신 타이머로 동작을 흉내 낸 예제입니다.

0:00 / 1:00 
<button type="button" aria-pressed="false" aria-label="재생">
  <svg aria-hidden="true" focusable="false">...</svg>
</button>
